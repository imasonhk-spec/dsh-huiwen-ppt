2026-10-08 用户在逐项访谈后确认：允许整套统一或主风格加局部融合；新风格提炼并扩展；保持单页信息量；未指定时每次推荐并确认；主体页以线性图标为主。用户对汇总执行方案回答“是”。此记录覆盖早先自动使用插画默认风格的选择规则，长期保存与复用授权继续有效。

## 组合边界

- 整套统一：全篇采用所选分支的字体层级、背景强度、图标与容器规则。封面和重点页可使用本分支明确允许的插画；简洁商务分支的这项例外不等于自动切换整页风格。
- 主风格＋局部融合：主风格决定母版、标题、字体、配色、页码、页底和背景强度。借用另一套风格的版式语义或少量主题素材，按主风格重新排版。内容字段、流程关系、数据结构可以共用。
- 简洁商务为主：功能表达以线性图标为主；本分支线描商务人物用于封面或场景重点页。2026-10-09 用户补充确认了此类人物，使用本分支人物属于统一风格内的组合。借用另一分支的立体插画仍需确认融合页。控制阴影、底座和装饰占用，按主风格重新排版。
- 办公插画为主：数据、对比、治理等页面可借用简洁分区与线性图标，同时沿用主风格标题、字号、配色和结论区。
- 一页选定主导图形语言。同一层级的同类图标保持线宽和画法一致；不同页的图表颜色保持同一语义。真实截图保留原貌、标明版本，不为统一风格改造事实画面。
- 不设置未经用户要求的固定混用比例。逐页说明是否融合、借用什么、为什么适合以及如何统一；用户确认后制作。用户提出变更时仅重确认受影响部分。

## 记录到项目

`brief.json` 中记录 `style_selection`：`mode` 为 `single` 或 `blend`，`primary` 为风格 ID，`secondary` 为另一风格 ID 或 null，`confirmed_by`、`evidence` 保留实际对话。`plan.json` 中每页补充 `style_family`、`layout_id`、`asset_ids`、`blend_elements`、`blend_reason`、`normalization`。融合页应有对应的实际确认记录。

这些是描述性设计字段，`studio.py build` 仍只依据已登记模板的 `source_slide` 与 `operations` 复用原生页；它不会自动读取字段并跨模板混合。融合页需要先在工作稿中实现、渲染，然后纳入当前项目。不要声称添加字段已实现自动融合引擎。

## 交付前核对

选择是否与用户明确回复一致；融合页是否和确认清单一致；新风格是否保留单页所需的任务、机制、输出和证据；密集页能否清楚阅读。每份 PPT 的素材保存授权、生成、渲染、编辑抽查与用户视觉验收分别记录。
